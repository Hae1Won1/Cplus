## 🆕 C언어에서 추가된 기능

- **함수 중복 (Function Overloading)**

  → 매개 변수의 개수나 타입이 다르면 동일한 이름의 함수 선언 가능

- **디폴트 매개 변수 (Default Parameter)**

  → 값이 전달되지 않으면 지정한 디폴트 값 사용

- **참조와 참조 변수 (Reference)**

  → 변수에 별명을 붙여 동일한 공간을 공유

- **참조에 의한 호출 (Call by Reference)**

  → 함수 호출 시 참조 전달 가능

- **new / delete 연산자**

  → 동적 메모리 할당(`new`), 해제(`delete`)

- **연산자 재정의 (Operator Overloading)**

  → 기존 연산자에 새로운 동작 정의 가능

- **제네릭 함수 / 클래스 (Template)**

  → 데이터 타입에 의존하지 않고 일반화 가능

## 🏛 C++의 객체 지향 특성

### 1) 객체와 캡슐화

- **캡슐화**: 데이터를 보호하고 외부 접근을 제한
- **클래스**: 객체를 정의하는 틀
- **객체(instance)**: 클래스에서 생성된 실체
- 멤버 변수는 보통 `private`, 접근은 `public` 함수로 간접 제공

### 2) 상속성 (Inheritance)

- 자식 클래스는 부모 클래스의 멤버를 물려받음
- 코드 재사용성 → 생산성 향상

### 3) 다형성 (Polymorphism)

- 하나의 기능이 다양한 방식으로 작동
    - **연산자 중복** (+ : 정수 덧셈, 문자열 연결 등)
    - **함수 중복 (Overloading)**
    - **함수 재정의 (Overriding)** : 상속 관계에서 부모 함수를 자식이 새로 구현

## 🧾 절차 지향 vs 객체 지향

### 절차 지향 프로그래밍

- C언어 방식
- **절차/순서 중심**으로 명령어를 나열
- 실제 세계를 표현하는 데 한계 존재

### 객체 지향 프로그래밍

- 실제 응용 세계를 **객체 단위**로 표현
- 절차 지향의 단점을 극복하기 위해 제안됨

---

## 🔧 제네릭 프로그래밍

- 함수와 클래스를 **데이터 타입과 무관하게 일반화**
- 같은 코드로 다양한 타입을 처리 가능
- 예: **제네릭 함수, 제네릭 클래스**
- → 10장에서 STL 라이브러리 학습

---

## ⚠️ C++의 부족한 점

- C와의 호환성 때문에 **캡슐화 원칙 일부 손상**
- 전역 변수 사용으로 인한 보안/의존성 문제

---

## 🔄 C++ 프로그램 개발 과정

1. **소스 작성**
2. **컴파일 (Compile)**
    - 문법 검사, 목적 파일(OBJ) 생성
3. **링킹 (Linking)**
    - 여러 목적 파일과 라이브러리를 묶어

      실행 가능한 기계어 코드(EXE) 생성

4. **디버깅 (Debugging)**
    - 오류 탐색 및 수정

➡️ **빌드(Build)** = 컴파일 + 링킹

## 📚 C++ 표준 라이브러리

- 다양한 함수와 클래스가 **미리 컴파일된 목적 파일** 형태로 제공
- 원시 소스 코드는 공개되지 않음
- 개발자가 호출해서 활용 가능**
